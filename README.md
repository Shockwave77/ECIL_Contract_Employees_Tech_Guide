# ECIL Contract Employees Tech Guide

Welcome to the technical guide and training repository for ECIL Contract Employees. This repository is structured to help you rapidly acquire and apply new technical skills through a **Project-First** guided learning approach. 

Whether you are brushing up on C programming, embedded systems, or new frameworks, this guide ensures you spend less time reading endless documentation and more time building.

## Our Learning Philosophy: Project-First

Traditional learning often starts with heavy theory, which can drain your interest and lack practical context. Here, we do the opposite. You will learn effectively in less time by getting your hands dirty with practical projects immediately. Theory is introduced exactly when you need it to solve a problem.

### Brief Workflow Overview
As a new user, your learning loop is simple: start a basic project task, refer to the theory archive only when you get stuck, and immediately practice applying that theory back into your project work.

## How to Navigate the Repository (Detailed Path)

Every skill in this repository (e.g., C Programming, Scripting, etc.) is divided into two main folders: **Project** and **Theory**. 

Follow this step-by-step workflow to get the most out of your training:

![Detailed Learning Workflow](images/Detailed_workflow.png)

### The Step-by-Step Process:
1. **Start Blind:** Navigate to a skill's `project/Basic/` folder and open the `problem_statement.md`. Attempt to solve the task (like printing "Hello World") even if you have zero theoretical background.
2. **Deploy & Observe:** If you find it impossible to complete as a beginner, navigate to the `ready_to_deploy` folder. Run the provided files just to see the expected output in action.
3. **Analyze the Source Code:** Open the `solution` folder and review the source code. Look specifically for **checkpoints** left in the comments (e.g., `// Skill Pointer: See Theory -> Malloc`).
4. **Targeted Theory:** Use those specific checkpoints to navigate directly to the `theory/Basic/` archive. Read only the specific theory file referenced by the code.
5. **Close the Loop:** Take the theoretical knowledge you just gained and apply it back to the project source code to understand exactly how and why it works.

By following this loop, you build practical intuition first and back it up with solid engineering theory second!
